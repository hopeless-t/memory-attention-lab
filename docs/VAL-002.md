# VAL-002 — Value-Source Decomposition

> **Status:** DESIGN FROZEN  
> **Scientific authority:** mechanism decomposition only  
> **Performance authority:** NONE  
> **Training authority:** NONE

## Goal

VAL-002 separates mechanisms that are otherwise easy to collapse into one
"Memory Attention vs Standard" comparison.

The primary question is not yet whether one model scores better.

It is:

> Which change produced which numerical difference in the value path?

## Primary causal lane

Freeze two binary factors:

~~~text
factor A: contextual value source
    Wv
    Wk

factor B: token memory
    OFF
    ON
~~~

This produces four cells.

### C00 — Standard

~~~text
V = X Wv
~~~

### C01 — Add-memory

~~~text
M = Norm(E_layer[token])
V = X Wv + M
~~~

### C10 — Key-reuse-only

~~~text
V = X Wk
~~~

### C11 — Memory Attention

~~~text
M = Norm(E_layer[token])
V = X Wk + M
~~~

The same memory table, normalization contract, token IDs, and value width must
be used in C01 and C11.

## What the 2 x 2 design identifies

It supports direct algebraic decomposition of:

~~~text
memory main effect
contextual-source main effect
memory x source interaction
~~~

For a scalar or tensor-valued observable Y:

~~~text
memory effect at Wv:
    Y(C01) - Y(C00)

memory effect at Wk:
    Y(C11) - Y(C10)

source effect without memory:
    Y(C10) - Y(C00)

source effect with memory:
    Y(C11) - Y(C01)

interaction:
    [Y(C11) - Y(C10)] - [Y(C01) - Y(C00)]
~~~

These are local controlled contrasts.

They are not automatically claims about trained-model quality.

## What it does not identify

Exact Memory Attention simultaneously:

~~~text
removes the dedicated Wv projection
and
reuses Wk as contextual value content
~~~

Therefore the primary 2 x 2 does not fully identify:

~~~text
generic projection sharing/removal
versus
a K-specific reuse advantage
~~~

If later evidence makes that distinction necessary, a new sentinel control must
be designed explicitly rather than silently inferred from these four cells.

## Historical Value Embedding lane

The historical mechanism cited by Memory Attention is not the same as the clean
C01 additive control.

The inspected 2024-12-04 modded-nanogpt record uses:

~~~text
V_hist = (1 - lambda) * X Wv + lambda * E_layer[token]
~~~

with a learned scalar lambda initialized to 0.5 in the inspected record.

Its role in this repository is:

~~~text
source-fidelity / lineage reproduction
~~~

not:

~~~text
the sole causal control for token memory
~~~

The historical lane must therefore have its own fixture and source identity.

## Frozen design spec

Machine-readable design contract:

~~~text
specs/VAL-002.json
~~~

The current spec is design-only. It does not imply that the executable
VAL-002 harness has been implemented.

## Planned acceptance contract

The first executable VAL-002 implementation should include deterministic
known-answer fixtures and verify at least:

~~~text
C00 matches dedicated Wv projection

C01 - C00 equals the frozen memory contribution M

C11 - C10 equals the same frozen memory contribution M

C10 uses Wk-derived content and no Wv contribution

C11 matches the frozen Memory Attention construction

factorial interaction arithmetic is internally consistent

historical VE reproduces the learned-lambda mixing equation

unknown fields / malformed shapes fail closed as INVALID

an intentionally swapped or post-RoPE key path is detected
~~~

## Framework strategy

Do not import the upstream implementation as the sole oracle.

Reuse the VAL-001 philosophy:

~~~text
small independent numerical contract first

framework adapter later, only when needed
~~~

The VAL-002 implementation may reuse the local independent VAL-001 numerical
helpers where the contract is identical.

## Evidence boundary

VAL-002 PASS will mean:

~~~text
the declared value-source decomposition executed correctly
under the frozen numerical contract
~~~

It will not mean:

~~~text
Memory Attention is better
Value Embeddings are worse
training will converge similarly
parameter-matched fairness has been established
latency is improved
GPU memory is reduced
~~~

Those belong to later experiments.
