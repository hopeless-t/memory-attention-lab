# VAL-001 — Memory Attention Algebra

> **Status:** FROZEN CANDIDATE  
> **Scientific authority:** validation only  
> **Performance authority:** NONE  
> **Training authority:** NONE

## Question

Can a small independent numerical oracle reproduce the frozen Memory Attention value-construction contract and detect common representation mistakes before any benchmark or training experiment begins?

## Why VAL-001 exists

The Memory Attention paper defines:

~~~text
M = Norm(E[token])
Q = X Wq
K = X Wk
V = K + M
~~~

For RoPE-based attention, the paper further distinguishes:

~~~text
content K
    |
    +----> V = content K + M

content K
    |
   RoPE
    |
attention/scoring K
~~~

This distinction is central to later MA-Recall work.

Using the positional/scoring key directly as the content contribution to V is not the frozen construction.

## Independent oracle choice

VAL-001 intentionally uses NumPy rather than importing FLA, FlashAttention, Triton, or the upstream model.

Reason:

~~~text
upstream implementation
        !=
independent validation oracle
~~~

If the same implementation path produced both the result and its expected answer, shared bugs could pass undetected.

The fixed expected arrays in the spec are independent known-answer fixtures.

A later stage may add a PyTorch adapter and compare it against this oracle.

## Frozen numerical contract

### Shapes

~~~text
T              sequence length
H_kv           number of key/value heads
D_h            head dimension
D_v=H_kv*D_h   flattened KV dimension

content_keys   [T, H_kv, D_h]
memory_table   [vocab, D_v]
token_ids      [T]
norm_weight    [D_h]
~~~

The normalization affine weight is shared across KV heads, matching the inspected use of RMSNorm(head_dim) in the public reference implementation.

### Head-wise RMSNorm

For each token and KV head:

~~~text
rstd = 1 / sqrt(mean(x^2) + eps)
Norm(x) = x * rstd * weight
~~~

The mean is over the head dimension only.

### Value construction

~~~text
selected_memory = E[token_ids]
normalized_memory = HeadwiseRMSNorm(selected_memory)
V = content_K + normalized_memory
~~~

### Folded inference table

At inference with fixed parameters:

~~~text
E_bar[i] = Norm(E[i])
V = content_K + E_bar[token]
~~~

VAL-001 requires the folded-table and online-normalization paths to agree within the frozen tolerance.

### RoPE boundary

The source implementation uses a non-interleaved GPT-NeoX-style rotary convention by default.

VAL-001 freezes that convention only to test the representation boundary and invertibility:

~~~text
content_K
    -> RoPE
    -> scoring_K

inverse_RoPE(scoring_K)
    -> content_K
~~~

VAL-001 is not a performance benchmark for positional reconstruction.

## Fixed known-answer fixture

The fixture deliberately contains:

- two KV heads;
- a four-dimensional head;
- non-unit RMSNorm affine weights;
- repeated token ID at different positions;
- different contextual keys for the repeated token;
- non-zero RoPE positions;
- values that make use of post-RoPE K detectably wrong.

Expected arrays are stored explicitly in the spec.

They are not generated at runtime by the code being tested.

## Acceptance checks

VAL-001 PASS requires all of the following:

~~~text
known_answer_normalized_memory
known_answer_constructed_values
known_answer_rotated_keys
folded_memory_equivalence
rope_roundtrip
same_token_same_memory_different_context
pre_rope_value_guard
~~~

The pre-RoPE guard deliberately computes the wrong variant:

~~~text
wrong V = RoPE(K) + M
~~~

and requires it to differ materially from the frozen correct result.

This is intentional failure injection.

## States

~~~text
PASS
    valid spec, execution completed, all checks passed

FAIL
    valid spec, execution completed, at least one check failed

INVALID
    spec rejected before scientific execution

ERROR
    runtime or I/O failure prevented valid evaluation
~~~

A PASS means only that this numerical contract is satisfied.

It does not mean Memory Attention is faster, more accurate, or superior.

## CI contract

GitHub Actions runs unit/failure-path tests across multiple standard hosted environments and then generates a canonical-candidate evidence artifact on a fixed Ubuntu/Python lane.

The generated artifact is short-lived CI evidence until explicitly reviewed.

It is not automatically committed as canonical evidence.

## Non-claims

VAL-001 does not test:

- downstream model quality;
- training behavior;
- FlashAttention correctness;
- GPU kernels;
- latency;
- CPU offload;
- MA-Recall performance;
- a 50% end-to-end memory saving;
- parameter-matched fairness.

Those belong to later stages.
