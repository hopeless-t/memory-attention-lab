# DS-001 — Stage 0 research sequence

> **Status:** ACCEPTED DECISION SUPPORT  
> **Scientific authority:** NONE  
> **Mainline implementation authority:** NONE  
> **Decision date:** 2026-09-25

## Question

Given the current literature and claim decomposition, in what order should the first executable research stages run?

Candidate stages:

~~~text
VAL-001
    Memory Attention algebra and reconstruction contract

VAL-002
    value-source decomposition

BENCH-001
    accelerator / host residency

BENCH-002
    value reconstruction / MA-Recall

EXP-001
    controlled small-model training
~~~

## Candidate sequences

~~~text
S1 lineage-first controls
    VAL-001 -> VAL-002 -> BENCH-001 -> BENCH-002 -> EXP-001

S2 systems-first
    VAL-001 -> BENCH-001 -> BENCH-002 -> VAL-002 -> EXP-001

S3 recall-first after controls
    VAL-001 -> VAL-002 -> BENCH-002 -> BENCH-001 -> EXP-001

S4 mixed
    VAL-001 -> BENCH-001 -> VAL-002 -> BENCH-002 -> EXP-001
~~~

## Decision criteria

The Monte Carlo perturbs explicit engineering priors over:

~~~text
causal identifiability
prerequisite coherence
early low-cost evidence
systems relevance
novelty pacing
reproducibility
~~~

These are not physical probabilities.

The calculation asks only whether the preferred engineering sequence remains stable when uncertain priorities and scores move.

## Baseline decision-support result

A 300,000-sample run with the frozen seed and priors in
research/stage0_sequence_mc.py selected:

~~~text
S1 lineage-first controls
~~~

in roughly 81% of simulated decision states in the design run.

The exact reproducible result is generated by GitHub Actions from the committed script.

## Council interpretation

The result agrees with the qualitative council reasoning:

1. VAL-001 is a prerequisite because MA-Recall is underspecified until the exact representation of reconstructable state is frozen.
2. VAL-002 should precede performance benchmarking because otherwise quality or behavior differences can be misattributed to Memory Attention when they may come from added token-indexed capacity.
3. BENCH-001 should precede MA-Recall because ordinary GPU/host residency establishes the transfer and measurement harness needed by reconstruction tests.
4. BENCH-002 can then measure a new storage-versus-reconstruction trade-off against a trusted baseline.
5. EXP-001 is intentionally last because training is more expensive and is harder to interpret before the mechanism and systems confounds are separated.

## Decision

~~~text
VAL-001
    ->
VAL-002
    ->
BENCH-001
    ->
BENCH-002
    ->
EXP-001
~~~

## Revisit conditions

Reopen this decision if any of the following occur:

~~~text
VAL-001 shows the assumed reconstruction relation is invalid or incomplete

the target hardware makes BENCH-001 impossible before another validation step

a cheaper experiment provides strictly higher information about a blocking uncertainty
~~~
